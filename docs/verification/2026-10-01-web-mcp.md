# App-owned MCP and actual web ChatGPT verification

Date: 2026-10-01 KST. Implementation base: `327fefd0` on
`codex/recovery-and-sonnet`. Scope: the user-requested personal-server MCP
preparation and actual web ChatGPT experiment through the in-app browser.
Contract: `docs/specs/external-ai-admission-slice.md` → App-owned MCP preparation.

## Result and authority

The normal app-owned room listener serves `/mcp`. Opening the existing public
ingress exposes that endpoint through the existing tunnel; a second MCP process
or tunnel is unnecessary. The invitation UI displays the current direct MCP
address and includes web registration and two-step admission instructions in
the existing guarded invitation copy action.

The existing ingress gate validates Host, Origin, local peer and proxy generation
before RMCP receives requests. Hosted invitations must match the current public
or local origin; their original capability reaches the same runtime's loopback
listener. The existing admission transaction still owns consumption, expiry,
permissions, revocation and retries. Remote private handles remain mandatory;
local stdio and explicit standalone remote-MCP contracts remain supported.

## Actual web experiment

An isolated macOS app (`app.agentsassemble.mcpcheck20261001`) was packaged and
Developer ID signed. Strict deep signature verification passed. This was a debug
package, without a notarization or distribution claim. The restored test room was
`room-20261001T010454`; ordinary user profiles and rooms were not used.

The app's normal invitation UI opened public ingress, displayed `/mcp`, created a
fresh one-use AI invitation and copied its registration/admission instructions.
Web ChatGPT in the in-app browser registered an isolated personal MCP connection
using the displayed endpoint and invoked actual tools. No manual server or
separate connector command was needed.

The initial web experiment passed. After correcting the preparation and wait
failures below, a fresh connection and invitation repeated the actual web flow:

posted an already-consumed test invitation into the disposable room; it is not
included in committed evidence or screenshots presented as the final result.

## Reproduced failures and corrections

- Public preparation accepted fabricated invite credentials before admission and
  could occupy the bounded private registry. Hosted preparation now requires the
  existing store to recognize the issued fingerprint before reserving capacity.
  An actual HTTP regression rejects 128 fabricated credentials and then admits
  a legitimate invitation. This lookup does not replace transactional admission.
- A hosted `room_wait_next` disconnected at the production 30-second HTTP
  lifetime because only its inner connector request retained authenticated wait
  authority. The admitted client now retains the enclosing HTTP lifetime after
  resolving its session and acquiring the wait cursor. The actual HTTP test crosses
  31 seconds of normal silence and then verifies bounded cancellation on shutdown.
- RMCP traces complete requests/responses, and the actual verbose app run exposed
  room message content through Tungstenite frame traces. The process logging owner
  suppresses both dependency targets globally, including target-specific overrides.
  This trades dependency payload diagnostics for credential/conversation privacy;
  product-owned failure reporting remains unchanged.

After the final logging correction, the signed package was rebuilt and restarted
with verbose global and explicit dependency filters. Its real WebSocket message
probe committed visibly, and its actual local HTTP MCP initialized and listed
17 tools. Trace logging remained active, while neither dependency payload events,
invite credentials nor either unique message/MCP probe appeared in the log. The
web functional flow preceded only this logging correction; the final package smoke
verifies that correction without claiming a third full web admission run.

## Cleanup and remaining limits

Both temporary personal ChatGPT connections were disconnected. Their uninstalled
definitions and test conversations remain recoverable; the original connector
and unrelated plugins were preserved. Public ingress was closed, the exact app
quit normally and all seven sampled process IDs across the final two runs were
confirmed absent. Owned app/profile/cache/WebKit data and copied invitation files
were moved to Trash after exit; the in-app test tab closed and Computer Use reset.

Evidence remains under `/tmp/aa-mcp-20261001/evidence/`: `web-result-final.txt`,
`web-message-final.png`, `web-confirmation-final.png`, `canonical-final.json`,
`log-privacy-final-package.json`, `process-cost-final.json`, test/build/gate logs
and `cleanup-final.json`. Copied invite files and raw profile logs remain only in
the isolated cleanup location; no bearer or private connection handle is committed.

Initial ChatGPT registration remains a manual external-account step. Quick-tunnel
addresses rotate, requiring registration of a new endpoint after rotation.
Persistent deployment, automatic reconnect across restart, public plugin-store
distribution, Windows/mobile flows and whole-product reviewer approval are not
proven by this scoped experiment. The existing stable-entry redirector is not an
MCP proxy and was not deployed or changed.
