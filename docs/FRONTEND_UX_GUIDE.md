# Frontend UX guide

프론트 변경 전에 읽고 실제 패키지 화면에 적용한다. Discord의 익숙한 대화·프로필·
맥락 메뉴 흐름을 유지하며, 아래 원칙은 Apple HIG와 Toss UX 가이드를 참고한다.
보안·권한·상태·재시도 계약과 기존 CSS/구조 게이트는 그대로 유지한다.

1. **가장자리 여백.** 내용·입력·버튼을 창 끝에 붙이지 않는다. 이 프로젝트의 기본값은
   패널 내부 좌우 24px, 섹션 간 20~24px, 버튼 간 8~12px다. 작은 팝업/창도 바깥
   여백 16px 이상과 안전 영역을 확보한다. 배경이 화면을 채워도 조작부까지 붙이지 않는다.
2. **한 화면에 한 작업.** 프로필은 카드 → 편집 → 한 번의 저장/취소로 연결한다.
   이름·사진은 저장 전 초안이며 취소로 버린다. 드물게 쓰는 설정은 필요할 때 펼친다.
3. **메뉴는 짧은 동작 목록.** 클릭한 이름·중복 제목·확인 문장·설명 문단을 메뉴에
   반복하지 않는다. 현재 대상에 가능한 동작만 표시하고 파괴적 동작은 아래에 둔다.
   우클릭과 보이는 더보기 버튼은 같은 동작으로 연결한다.
4. **확인은 별도 작업.** 강퇴·영구 종료·삭제처럼 중요한 결과는 선택 후 확인한다.
   대상과 결과를 한 번만 안내하고 취소와 해당 동작만 둔다. 확인 중 뮤트 등 다른
   동작을 섞지 않는다. 일반 저장/가역적 편집에 추가 확인을 붙이지 않는다.
5. **버튼 역할과 문구.** 주요 동작 하나를 강조하고 취소는 보조, 위험 동작은 위험
   스타일로 구별한다. '확인'보다 '강퇴', '방 삭제'처럼 결과를 말한다. 터치 대상은
   최소 44×44 CSS px로 잡고 버튼·아이콘 주변 공간을 확보한다. 변경 전 저장은 비활성화한다.
6. **짧고 정확한 안내.** 자연스러운 해요체와 동작 중심 문구를 쓴다. 이미 보이는 이름,
   버튼 의미, 내부 API/런타임 구현을 반복하지 않는다. 실패 이유와 다음 행동은 숨기지 않는다.
7. **초점과 실패.** 메뉴/창은 밖 클릭·Escape·취소로 예측 가능하게 닫힌다. 확인 창은
   배경을 비활성화하고 초점을 소유하며, 닫힌 뒤 진입점으로 복귀한다. 저장 중 중복 제출을
   막고 실패 시 초안을 유지한다. 성공 표시는 서버가 확정한 상태를 따른다.
8. **완료는 실제 조작으로 판단.** 데스크톱과 390px 폭, 낮은 높이의 창에서 열기·편집·
   취소·저장·오류·메뉴·스크롤을 조작한다. 긴 이름, 메뉴 하단/우측, 포커스 테두리,
   마지막 입력/버튼이 잘리거나 끝에 붙으면 수정 후 다시 확인한다. 테스트 통과만으로
   시각적 완료를 선언하지 않는다. 단계별 검증 기록은 VERIFICATION.md가 소유한다.

24/16px 등 수치는 원문을 복제한 규정이 아니라 이 프로젝트의 적용 기준이다.

참고 원문 (2026-09-07 확인):
- [Apple Layout](https://developer.apple.com/design/human-interface-guidelines/layout): 정렬·여백·안전 영역·창 크기 적응.
- [Apple Context menus](https://developer.apple.com/design/human-interface-guidelines/context-menus): 짧고 관련 있는 동작, 불필요한 제목 생략.
- [Apple Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts) · [Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons): 필요한 확인, 명확한 결과, 역할·간격·조작 영역.
- [Toss UI/UX](https://developers-apps-in-toss.toss.im/design/consumer-ux-guide.html): 일관된 해요체, 능동적이고 맥락에 맞는 안내. 앱인토스 전용 배포/브랜딩 규칙은 이 제품에 적용하지 않는다.
